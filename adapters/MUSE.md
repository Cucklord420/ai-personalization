# Apply to an existing Muse workspace

Read live files and use the supported editing/import mechanism. Preserve newer facts, the chosen name/avatar and local instructions. This guide does not claim Muse was updated.

| Live file, if present | Profile content | Preserve |
|---|---|---|
| USER.md | Stable preferences and topic constraints | Newer explicit corrections |
| MEMORY.md | Dated useful facts/decisions | Sources, status, uncertainty |
| SOUL.md | Practical, clear collaboration style | Existing persona/boundaries |
| IDENTITY.md | Explicitly chosen identity only | Existing name/avatar |
| AGENTS.md | Work/research/verification rules | Platform permissions |
| TOOLS.md | Actually observed setup/access notes | No invented endpoints |
| PROACTIVE_PREFERENCES.md | Monitoring/delivery rules | Task times and alert history |
| HEARTBEAT.md | Due authorized real checks only | Actual schedules/state |

Criteria: file responsibility, supported facts and live-state preservation.

Read context/monitoring.md and CONFLICTS.md. Reconcile older assumed active watches with newer records. A nonempty heartbeat can cause an existing worker to do work; it is not proof of scheduling. Do not duplicate, enable or transfer watches just to import personalization.

Merge stable USER/AGENTS behavior first. Change operational checklists only within the actual authorized task after inspecting schedules and state. Preserve Muse's chosen identity; do not impose it on other AIs. An export does not prove restoration or capability transfer.

TCO: no added paid editing software is required. Existing Muse plan, usage, background-runtime and context costs remain unverified.
